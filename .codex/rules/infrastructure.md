# Infrastructure layer

- In V2, place Drizzle schemas, mappers, repositories and transaction adapters under
  `infrastructure/persistence/drizzle/{schemas,mappers,repositories,transactions}/<area>/`.
  Put other outbound adapters under `infrastructure/adapters/<integration>/`. Follow checked-out
  paths in modules awaiting migration.
- Infrastructure implements application ports. Bind those implementations in composition.
- Repositories implement the ports declared by the application layer; they map rows to domain
  objects and back, nothing more.
- Use the ORM already declared in package.json; never add a second one.
- Queries on a tenant table filter on `organization_id`; queries on a table without an
  organization (accounts, codes) or of an account that names an organization (sessions, the last
  organization chosen) name their rows by key. Lists are paginated; every query is backed by an
  index.
- External clients (payment, email, Git providers, storage) sit behind a port with a fake for tests.
- This service reads and writes **only its own database**.
- The ORM is Drizzle (`drizzle-orm` over `pg`); migrations are generated by `drizzle-kit` from the
  `*.schema.ts` files of this layer.
- Naming, common columns, row-level security, enumerations, pool size and timeouts follow the
  `cw-database-conventions` skill: load it before writing a schema or a query.
